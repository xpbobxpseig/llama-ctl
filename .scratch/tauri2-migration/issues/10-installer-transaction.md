# 10: installer — 官方更新事务与失败回滚

**What to build:** 把官方更新的安装事务移植到 Rust：下载 → 停服 → 备份 → 逐文件替换 → 重启，任一步失败精确 Rollback 已替换文件，收尾尽力重启服务。用户视角：点「立即更新」后能看到逐步进展，失败了工具会把文件恢复到原样并尽力把服务拉起来，绝不静默留下停摆的服务或半替换的二进制。

这是领域层里唯一有真实依赖的模块（依赖 updater、服务控制、文案），所以排在最后。

**Blocked by:** 04, 05, 06, 08

**Status:** ready-for-agent

- [ ] 完整序列：停止服务 → 下载（已缓存则复用）→ 备份旧文件到带时间戳目录 → 逐文件原子替换 → 重启并确认 RUNNING
- [ ] 备份失败即中止，且未替换任何文件
- [ ] 替换过程记录已替换清单，任一步失败精确 Rollback 已替换文件
- [ ] 失败收尾尽力重启服务，绝不静默留下停摆服务
- [ ] 进度日志逐行输出，可被前端实时消费
- [ ] 替换目标优先按服务的安装目录推导，推导失败时回退环境变量
- [ ] 用注入的假依赖在无网络、无服务的环境下跑完整条失败/回滚路径

- [ ] 注意术语区分：Rollback 是这里的失败路径，不是用户主动的 Revert
