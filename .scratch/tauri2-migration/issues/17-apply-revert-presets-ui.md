# 17: 应用更改 / 还原 / 预设 UI 与未应用更改提示

**What to build:** 表单的提交侧：应用更改的二次确认与新旧参数对比、还原按钮、未应用更改提示，以及预设的可编辑下拉（保存 / 即选即载 / 删除 / 自动备份）。用户视角：改参数时随时知道自己改了什么，且不会被静默写入服务。

注意术语区分：这里的「还原」是用户主动丢弃表单改动的 Revert，不是更新失败路径的 Rollback。

**Blocked by:** 13, 07, 11

**Status:** ready-for-agent

- [ ] 有未应用更改时显示明确提示
- [ ] 还原按钮只在有未应用更改时可用
- [ ] 应用更改前展示新旧参数对比并二次确认
- [ ] 未应用更改的判定走语义等价，别名/顺序/缺省默认值差异不算改动
- [ ] 应用更改按钮自身按文本比较决定是否提示「无变化」（写回是规范化动作）
- [ ] 写回成功后同步覆盖当前同名预设
- [ ] 预设名为可编辑下拉框（输入与选择合一）
- [ ] 预设：保存（同名已存在则 no-op）/ 即选即载（不写服务）/ 删除（二次确认）
- [ ] 表单有未应用更改时切换预设或服务，先确认并提供自动备份（名字带时间戳）
- [ ] 组件测试覆盖：提示显隐、还原按钮可用性、确认对话框触发时机、预设增删载
