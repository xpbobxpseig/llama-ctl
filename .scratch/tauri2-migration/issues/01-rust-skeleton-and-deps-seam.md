# 01: Rust workspace 骨架、Deps 注入接缝与 CLI 驱动

**What to build:** 立起 Tauri 2 工程的骨架：Rust workspace 与模块布局、贯穿全局的错误类型与 serde 约定、以及**依赖注入接缝** —— 一个 `Deps` trait，把所有外部副作用（子进程、注册表、网络、文件系统）收拢进去，领域函数不直接调用系统 API。同时提供一个命令行入口，能调用任意一个领域操作并打印结果。

用户视角：这一片本身没有可见功能，但它让后续每一张票都能独立演示与验收 —— 领域层在没有前端的情况下也能被驱动和测试。

先立起这个接缝而不是让领域代码直接调系统 API，是因为现有 Python 代码已经证明这个形状好用：`installer.RealDeps` 让整个更新事务能用假实现在无 UI、无网络、无服务的环境下跑完整失败/回滚路径。照搬这个形状，而不是发明新的。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] Rust workspace 建好，模块按领域划分（参数、服务事实、更新、安装事务、持久化、文案）
- [x] 一个 `Deps` trait 覆盖全部外部副作用：子进程 spawn、注册表读取、网络请求、文件系统读写
- [x] 同一 trait 有一份「真实现」与一份「测试假实现」，假实现可记录调用次数
- [x] 统一错误类型：覆盖系统命令失败、解码失败、网络失败、文件失败，且携带可用于界面展示的消息
- [x] serde 约定就位：领域结构的序列化形状确定，前端按此形状消费
- [x] CLI 入口可调用领域操作并输出结果，无需启动 GUI
- [x] `cargo test` 能跑通一个最小用例，证明测试假实现可用
- [x] 不为 Linux / macOS 留任何 trait、seam 或 cfg 分支（ADR-0003）
