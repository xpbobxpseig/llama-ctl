llama.cpp Service Console
应用图标三方案

现版本的问题不在绘制质量，而在语义：蓝色渐变底板与终端提示符只说明“这是一个控制台”，没有说明本地模型、服务状态和控制关系。以下方案均以 16px 可辨识为硬门槛，只使用现有品牌色。

本轮判断标准

每个候选都同时看真实尺寸、黑色轮廓和状态承载方式。推荐方案不是主观偏好，而是在 16px 下保留最多语义的方案。

01 / FOUNDATION

先修语义，再修外形

终端提示符是工具类型，不是产品身份。新图标必须同时说出“本地模型”和“可控服务”，并且不能依赖大尺寸下才成立的细节。

缺陷 01斜向蓝色渐变

#4aa6ff → #055ad4，表面明度比 2.39:1。视觉语言偏旧，且同一白色标记的对比度从 2.56:1 波动到 6.14:1。

缺陷 02主体是 >_ 提示符

它只说明“终端控制台”，无法说明 llama.cpp、本地模型、推理服务或进程控制。

缺陷 0316px 状态点失效

原绿色圆点在 16px 下约 3.8px，缩小后像模糊色斑，难以稳定表达“服务运行中”。

处理结果三案全部重建语义

去掉渐变与终端提示符；使用平板底板，并把状态改为完整槽位、轨道或由主体健康脉冲承担。

平板化底板

三案均为纯色底板，明度比 1.00:1；不恢复斜向渐变、高光、内阴影或厚重投影。

16px 优先

缩到 16px 后仍能识别主要轮廓；不放细线、不保留靠颜色才可分离的相邻形状。

表达本地 AI 服务

使用羊驼、模型层、节点网络和机架槽位中的两类语义组合，不把终端提示符作为主体。

状态不是装饰

保留状态时必须使用连续形状或完整槽位；不再使用 16px 下不可辨认的小圆点。

02 / CANDIDATE A

方案 A · 巡诊羊驼

用羊驼侧脸直接说明本地模型，用贯穿身体的心电脉冲说明服务健康。轮廓优先，状态不另加小圆点。

LLAMA + HEALTH PULSE

羊驼本体就是服务状态

白色羊驼侧脸占据主要视觉区域，颈部内嵌蓝色脉冲线。脉冲在 32px 以上可读，16px 时即使细节丢失，头部与耳朵仍能维持独特轮廓。

纯色蓝底板 无独立状态点 语义最直接

设计依据

识别优势

羊驼侧脸与耳朵形成非对称轮廓，不依赖颜色或内部细节，16px 仍能区别于通用工具图标。

状态策略

不加右上角状态点。健康语义由脉冲线承担，避免小尺寸状态下出现不可读的绿色像素。

底板

#0b5cb0 纯色，圆角半径 52/256，适合 Windows 圆角方形图标外壳。

代价

脉冲线在 16px 下会消失，只剩羊驼本体；用户会先识别“本地模型”，再在大尺寸界面中读到“健康”。

几何约束

羊驼头部保持在 32–210 单位范围内，最大边距 46 单位；耳朵顶点不低于 58 单位。脉冲线使用 10 单位圆角描边，与大图标视觉重量一致。

未保留独立圆点。如果后续必须增加运行状态，建议在大图标之外的状态卡中使用现有 dot-run 图标，不进入应用图标。

03 / CANDIDATE B

方案 B · 机架节点

三层机架槽位表达本地服务，节点网络表达模型推理，绿色整层槽位承载运行状态，不需要额外小圆点。

SERVICE RACK + MODEL NODES

服务进程与模型网络同时出现

两条白色机架槽位表示受控进程，顶部蓝色节点线表示模型计算；第三条槽位通体使用成功绿，说明服务正在运行。缩到 16px 后仍能看到三根横向服务带。

纯墨黑底板 绿色整层状态 16px 稳定性最高

设计依据

识别优势

横向槽位天然适配 Windows 小图标，边缘清楚，抗模糊能力优于细线条和复杂轮廓。

状态策略

保留状态，但不保留小圆点。绿色下槽完整有效，宽 160 单位、高 38 单位，在任何尺寸都作为形状存在。

底板

#18181b 纯色，白色与蓝色元素提供清晰对比，适合深浅两种任务栏背景。

代价

“本地 AI”主要依赖蓝色节点线，16px 时节点会合并；机架语义仍然成立，但不如羊驼具体。

状态尺寸

绿色下槽在 256 画布中为 160 × 38 单位，分别渲染为 16px：10.00 × 2.38px；24px：15.00 × 3.56px；32px：20.00 × 4.75px；48px：30.00 × 7.13px；64px：40.00 × 9.50px；128px：80.00 × 19.00px；256px：160.00 × 38.00px。

04 / CANDIDATE C

方案 C · 模型叠层

三层模型块表达本地权重文件，节点连线表达推理网络，底部整层绿色表达服务受控且健康。整体更接近“模型资源”，弱于“进程控制”。

MODEL LAYERS + SERVICE RAIL

把本地模型当成一块可管理的资源

白色底板配蓝色边框，两层蓝色模型块表达本地模型文件；内部节点连线说明 AI 模型，底部整层成功绿承载可控运行状态。

白色纯色底板 绿色底部整层 通用 AI 语义

设计依据

识别优势

三层模型块在 16px 下形成规则堆叠轮廓，阅读速度快，适合任务栏与文件关联图标。

状态策略

第三层整体使用成功绿，作为完整横向形状存在。16px 时可读为绿色服务层，而不是状态点。

底板

#ffffff 纯色底板配 #0b5cb0 10 单位边框，浅色系统中仍保持边界。

代价

节点与堆叠层更像通用 AI 资源图标，必须依靠应用名称和界面上下文补足“llama.cpp 服务控制”的含义。

状态尺寸

绿色第三层在 256 画布中为 158 × 42 单位。16px 时对应 9.88 × 2.63px，24px 时为 14.81 × 3.94px；连续面积足够稳定承载“运行中”，不需要额外状态点。

06 / RECOMMENDATION

推荐方案：巡诊羊驼

产品名称已经包含 llama，图标正需要用最少的形状把这个名字变成资产。

RECOMMENDED / CANDIDATE A

先品牌识别，再服务状态

方案 A 是唯一能在 16px 下同时保留独特轮廓和“llama”名称联想的候选。它与 llama.cpp Service Console 的产品身份直接一致，不会像机架或模型叠层那样落入通用服务器或通用 AI 工具的外观。

状态指示应留在应用界面内部：状态卡继续使用现有 dot-run 图标，应用图标本身不再塞入小绿点。落地时按本页轮廓把吻部收直、耳朵拉开，并在 14px 至 18px 区间单独做一次像素预览，确保任务栏尺寸仍然清楚。

08 / HANDOFF

从 SVG 到 Windows 图标资源

交付时保留 256 单位 SVG 源文件，再按 Windows 所需的实际尺寸导出 PNG 或 ICO；不要重新画小尺寸版本。

SVG 源文件

使用 256 × 256 viewBox；所有坐标保持整数或 0.5 单位；底板圆角半径固定 52 单位。颜色写在构建映射中，不写在路径内部。

导出尺寸

至少输出 16、20、24、32、40、48、64、128、256 px，并生成多尺寸 ICO。16–24px 复核描边和状态色，不单独改变主体比例。

验收检查

在 Windows 浅色任务栏、深色任务栏、文件资源管理器、开始菜单和窗口标题栏各查看一次；任何尺寸都不得出现彩色边、糊边或状态色丢失。
