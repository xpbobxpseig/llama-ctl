# llama_ctl UI 重设计方案（待确认）

> 状态：**待确认**。确认前不改动任何代码。
> 目标：把界面从「Apple 风浅色设置面板」升级为**现代、简约、时尚**的桌面控制台，
> 功能与交互语义完全不变。

本文所有数字来自对**现有程序的实际测量**（隔离 settings 启动 + 截图分析 + Tk 控件内省 +
WCAG 对比度计算），非估计值。

## 一、现状诊断（实测）

### 1.1 结构现状

| 项 | 实测值 |
|---|---|
| 技术栈 | Python + CustomTkinter 6.0.0，单文件 GUI `llama_ctl_gui.py`（2946 行） |
| 窗口 | 代码默认 1000×860，最小 920×720（逻辑 px）；实测环境 DPI 缩放 1.5 |
| 参数 | 28 字段 / 7 折叠分组（模型与视觉 3、加速 4、上下文与显存 4、并发与吞吐 4、采样 7、网络 2、高级 4） |
| 控件构成 | slider 11、combo 5、check 5、text 4、path 3 |
| 布局 | 标题行 → 状态卡 → 预设卡 → 参数卡（滚动）→ 日志条，全部单列 `pack(fill=x)` 堆叠 |
| 参数区高度 | 全部 7 组展开时表单内容高 **1332 逻辑 px**，而窗口总高仅 860 → 必然出现滚动；默认只展开前两组时约 534 |

### 1.2 实测到的问题

**P1 — 设置页混用 CTk 默认蓝，与主界面不同色**
设置窗 3 个下拉实测取色 `fg_color=['#3B8ED0','#1F6AA5']`、`button_color=['#36719F','#144870']`，
即 CustomTkinter 内置默认蓝，**未接入项目调色板**。
截图统计：`#3b8ed0` 占 29 472 像素，而项目强调蓝 `#0a84ff` 仅 1 091 像素。
同一个应用出现两种蓝，是最显眼的不一致。

**P2 — 浅色主题大面积对比度不达标**（WCAG AA 正文要求 ≥ 4.5）

| 颜色 | 用途 | 实测（卡片上 / 页面上） | 结论 |
|---|---|---|---|
| `#ff9500` ORG | 未应用更改提示、警告行 | 2.20 / 2.02 | 远低于 4.5 |
| `#30d158` RUN | 运行中状态点 | 2.02 / 1.86 | 图形也低于 3.0 |
| `#aeaeb2` GRAY | 滚动条 | 2.21 / 2.03 | 低于 3.0 |
| `#8e8e93` STOP | 停止状态点 | 3.26 / 2.99 | 低于 4.5 |
| `#86868b` MUT | 全部次要文字 | 3.62 / 3.33 | 低于 4.5 |
| `#0a84ff` ACC | 强调 / 链接 | 3.65 / 3.35 | 低于 4.5 |
| `#ff3b30` RED | 危险按钮文字 | 3.55 / 3.26 | 低于 4.5 |

**P3 — 深色主题 hover 方向反了**
`ACCH #0071e3` 比深色卡片 `#2c2c2e` 更暗（对比度 2.97）。深色下悬停本应变亮，现在变暗。

**P4 — 同一张卡里 5 种右对齐位置，视觉发散**
参数卡内控件右边缘实测（1100 宽窗口，逻辑 px，卡内可用宽 1025）：

| 控件类型 | 实测右边缘范围 | 浪费的右侧空间 |
|---|---|---|
| check | 201 – 286 | 739 – 824 |
| combo | 394 – 479 | 546 – 631 |
| path | 911 – 925 | 100 – 114 |
| text | 911 – 1021 | 4 – 114 |
| slider（数值列顶到最右） | 1025 | 0 |

- 同类控件内部也不一致（path 911–925、text 911–1021）
- 空白的**中位数 100 逻辑 px、最大 825 逻辑 px**

**P5 — 滑块与它的数值之间隔着一条「空心带」**
滑块轨道固定 `width=300`，数值标签固定贴最右（915–1025）。实测轨道右端与数值左端之间：

| 参数 | 轨道 | 数值 | 中间空洞 |
|---|---|---|---|
| `ngl` / `spec_draft_n_max` | 259–559 | 915–1025 | **357** |
| `ctx_size` | 208–508 | 915–1025 | **407** |
| `parallel`/`batch_size`/`ubatch_size`/`threads` | 171–471 | 915–1025 | **445** |
| `temperature`/`min_p`/`top_k`/`top_p` | 287–587 | 915–1025 | **329** |

即 11 条滑块每一条中间都有 329–445 px 的空洞，占了卡宽的近一半。

**P6 — 固定像素宽度不随窗口伸缩**
slider 固定 `width=300`、combo 固定 `width=220`、服务与自启下拉 `width=220/110`、预设框 `width=300`。
窗口从 920 拉到 1100（卡内可用宽 845 → 1025，增加 180），
combo 右边缘仍是 394–479、宽度恒为 220，多出来的宽度全部变成右侧空白。

### 1.3 应保留的资产（不推翻）

- 全部业务逻辑与安全策略：二次确认、语义等价判定、更新事务与回滚、后台 worker
- 动效引擎 `motion.py`（指数渐隐、呼吸圆点、30s 无交互静止）——成熟且克制
- 图标体系 `assets/icons`（双主题双帧 PNG + 缓存）与测试守卫
- 折叠分组、问号提示、快捷档位、预设 / 日志折叠等交互结构

## 二、设计方向

### 2.1 定位

> **「仪器面板」而非「设置窗口」**：信息密度高但呼吸充分；
> 层级靠**字重与灰阶**而非边框堆叠；颜色只用于「当前状态」与「唯一主操作」。

### 2.2 三条原则

1. **少一种颜色，多一级秩序** — 现状 8 种语义色平铺；新版收敛为 1 强调色 + 3 状态色，
   状态色只用于状态点与提示条，不作装饰。
2. **一套栅格，一条右准线** — 所有行控件右边缘对齐同一准线，控件随窗口弹性伸缩，
   消除 5 种参差与 440px 空洞。
3. **静止即默认** — 动效关闭时行为完全等价（沿用现有约定）；悬停 / 聚焦共用 100ms / 0.8s 节奏。

### 2.3 新配色（逐项经 WCAG 验证）

浅色：

| Token | 值 | 用途 | 对比度（页面 / 卡片 / 次级面） |
|---|---|---|---|
| `page` | `#f4f4f6` | 窗口底 | — |
| `surface` | `#ffffff` | 卡片 | — |
| `surface2` | `#f7f7f9` | 输入框 / 内嵌区 | — |
| `border` | `#e6e6ea` | 分隔线 | 装饰性 |
| `ink` | `#18181b` | 主文字 | 16.13 / 17.72 / 16.56 |
| `ink2` | `#52525b` | 次要文字 | 7.04 / 7.73 / 7.22 |
| `ink3` | `#5f5f66` | 辅助文字 | 5.77 / 6.33 / 5.92 |
| `accent` | `#0b5cb0` | 强调文字 / 链接 | 6.03 / 6.62 / 6.19 |
| `accentFill` | `#0a6fd6` | 主按钮底（白字 4.93） | — |
| `ok` / `warn` / `err` | `#0f7b3d` / `#9a5b00` / `#c2261c` | 状态文字 | 4.88 / 4.94 / 5.33 起 |

深色（强调色提亮；hover 变亮）：

| Token | 值 | 对比度（页面 / 卡片 / 次级面） |
|---|---|---|
| `page` / `surface` / `surface2` | `#121214` / `#1c1c1f` / `#26262a` | — |
| `ink` / `ink2` / `ink3` | `#f4f4f5` / `#b4b4bd` / `#8e8e97` | 17.02 / 9.09 / 5.76 起 |
| `accent` | `#4da3ff` | 7.13 / 6.48 / 5.74 |
| `accentFill` | `#0a6fd6`，hover `#1275da` | 白字 4.93 → 4.58（同向变亮且仍达标） |
| `ok` / `warn` / `err` | `#4ade80` / `#fbbf24` / `#ff6b61` | 10.74 / 11.21 / 6.71 起 |

> 关键改动：把「强调蓝」拆成 **accentFill（填充）** 与 **accent（文字）** 两个角色。
> 原 `#0a84ff` 作白字底仅 3.65、作文字也仅 3.65；拆开后两侧均过 AA。

### 2.4 栅格与尺寸

- 间距梯度：`4 / 8 / 12 / 16 / 24 / 32`（现状 2/4/6/8/12/14/16 混用）
- 圆角梯度：卡片 `12`、控件 `8`、徽标 `6`（现状 14/10/8/6/13 混用）
- 参数行三列：`标签 200px 固定` + `控件 弹性 fill` + `数值 / 动作 88px 固定`
- 窗口默认 `1040×880`，最小 `940×720`；控件全部随窗口伸缩

### 2.5 字体与层级

| 层级 | 字号 / 字重 | 现状 |
|---|---|---|
| 页面标题 | 20 semibold | 18 bold |
| 卡片标题 | 11 medium + 字距 | 12 bold 灰 |
| 字段标签 | 13 regular | 13 regular |
| 数值（等宽） | 13 medium | 12 Consolas 灰 |
| 辅助说明 | 12 regular `ink3` | 12 `MUT` |

## 三、主要界面调整建议

### 3.1 顶栏

标题左、服务下拉右，中间大片空白。改为左侧「应用名 + 当前服务名」两行
（20 semibold / 12 `ink3`），右侧保留服务下拉并改自适应宽度（200–280），
底部加 1px 分隔线与内容区分离；高度 56px，左内边距对齐 24px 准线（现状 16px）。

### 3.2 状态卡（重点）

现状一行塞 8 个元素（圆点、状态、服务名、探活、自启下拉、4 个按钮），信息平权，主操作不突出。

改为两行：
- 第一行：`状态点 + 状态文字`（15 medium）｜右侧 `探活 · 延迟` 灰字
- 第二行：`开机自启` 开关（宽 96）｜右侧操作区

操作区：`启动` 为**唯一 primary 填充按钮**；`停止`、`重启` 为中性描边按钮；
`设置` 降为右上角图标按钮。危险色仅在「停止」可用且服务运行时出现。
高度 56 → 76px，换来主次分明。

### 3.3 参数区（收益最大）

现状 7 组 / 28 行：全部展开时表单内容 1332 逻辑 px，而窗口总高仅 860；
每行右边缘参差（5 种位置），11 条滑块中间各有 329–445 px 空洞。改为：

1. **三列栅格**：`问号(26) + 标签(200) + 控件(弹性) + 数值(88)`，
   全部 `sticky="ew"`，右边缘统一到卡内右准线。
2. **滑块改为「轨道弹性 + 数值右对齐」**：轨道 `fill=x`，数值贴右准线，
   间距 ≥24px，消除中间空洞。
3. **分组头重做**：`chevron + 组名 + 参数个数徽标`；展开时组名用 `accent`，
   收起用 `ink2`；组间加 1px 分隔线 + 24px 间距（现状仅 6px）。
4. **降低滚动焦虑**：保持「前两组默认展开」，组内行高 34 → 32，组头 sticky。
5. **未应用更改**：由预设行橙字改为**卡片右上角徽标**（`warnSoft` 底 + `warn` 字 + 圆点），
   并在卡片底部显示**操作条**（`应用更改` primary + `还原` 文字按钮），仅在 dirty 时出现。

### 3.4 预设区

现状一行 6 个元素。改为：预设下拉独占一行（弹性宽度），右侧仅留删除图标；
「应用 / 还原」移入参数卡操作条。高度 56 → 48px。

### 3.5 日志区

折叠条改为「日志尾随 server.err」+ chevron + 行数徽标；展开高度 40 → 220px，
等宽 12、行高 1.5，新行沿用现有 flash 高亮。警告行并入日志卡顶部，不再独占一行。

### 3.6 设置窗口

统一接入新调色板（修 P1）；改为 `左标签 140px / 右控件` 两列对齐；
分「界面 / 外观 / 动效 / 官方更新」四小节，节间 1px 分隔线；窗口 600×640；
底部 `关闭` 按钮右对齐（现状居中）。

### 3.7 细节

- 滚动条宽 8 → 6，颜色 `border`（替代对比度不足的 `GRAY`），悬停 `ink3`
- 所有输入控件增加 2px `accent` 焦点描边（现状几乎无焦点反馈）
- 禁用态统一 `ink3` + 40% 不透明度
- `seed` / `port` 等数值输入右对齐等宽

## 四、影响与取舍

| 项 | 说明 |
|---|---|
| 改动范围 | `llama_ctl_gui.py` 的 `PALETTES`、`_build_widgets`、`_card`、`_btn`、`_build_field`、设置窗构建 |
| **不动** | `params.py`、`nssm_adapter.py`、`updater.py`、`installer.py`、`presets.py`、`settings.py` 的业务逻辑 |
| 测试基线 | 改造前实测 **244 passed**（全绿），改造后须保持全绿 |
| 测试影响 | 现有用例不校验调色板与布局数值；`test_icons_assets` 的接入层断言（`ic.chevron(`、`ic.glyph("question"`、`ic.glyph("trash"`、`ic.set_appearance(resolved)`）必须保留 |
| 新增测试 | 1 个纯函数单测：对每个 token 断言对比度达标，防未来改色回退 |
| 风险 | ① 控件改弹性后需回归英文界面不溢出（现有 en 长度测试守护）② 状态卡重排须保留 `btn_start` / `btn_stop` / `btn_revert` / `btn_apply` 等既有属性名 |
| 依赖 | 无新增依赖 |

## 五、确认方式

请择一回复：

1. **全部确认** → 按此实施，并跑全量测试 + 双主题截图对照。
2. **只做视觉层**（调色板 + 对比度 + 圆角 / 间距，不改布局）——风险最小，见效最快。
3. **只做布局层**（栅格 + 右准线 + 状态卡重排，调色板不动）——解决「散」，但颜色问题保留。
4. **调整某项** → 指出要改的条目（如「状态卡不要改」）。

> 现状截图（浅色 / 深色 / 设置页）与量化脚本存于会话 scratch，可直接打开比对。
