## 0. 一页结论

**换的不是配色，是任务模型。**

v3 把窗口当成一块"仪表盘"：一个 280px 服务栏、一条通栏底栏、一个 28px 的状态词，所有东西同时在场。结果是**没有一个区域是主角**，而且这个布局把"看状态"和"改参数"这两种频率、风险完全不同的工作压进了同一个平面。

v4 的判断是：这个工具只有**一件事**需要永远在场——**当前服务的真实状态**；其余都是**按任务分区的模式**：

```
App bar       品牌 · 命令面板 · 设置
Sidebar       服务列表（多服务切换、状态点、刷新）
Workspace     ┌ 身份 + 真值行 + 上下文动作
              ├ 模式页签：参数 / 预设 / 维护
              ├ 内容（唯一滚动容器）
              └ 提交条（有未应用更改时才出现）
Dock          活动 / server.err —— 常驻，折叠成 32px
```

三条设计原则：

1. **一条真值行（Truth line）。** 状态、探活、地址、版本、自启、安装目录压缩成一行等宽字；全窗口只有这一处表达状态，不存在第二个"状态 pill"。
2. **一个主按钮（One filled action）。** 填充按钮永远在内容区（应用更改 / 立即更新），窗口框架上不出现第二个填充按钮；颜色不承担"层级"，层级由填充 vs 描边 vs 文字承担。
3. **改动先审阅（Review before write）。** 未应用更改在四层可见（页签角标、分区计数、行内原值、提交条），"应用"先开变更审阅浮层再看差异——差异不再藏在确认对话框里。

视觉坐标：**中性石墨 + 一个冷蓝交互色 + 墨色主按钮**，密排、小字号、发丝线、只有浮层有阴影。目标气质：*安静的开发工具*，而不是*文具式的仪器*。

## 1. Visual Theme & Atmosphere

**一句话**：一块深石墨工作台，机器数据用等宽字，人读的文案用 13px 无衬线，所有边界是一根 1px 的线。

- **安静优先**：静止界面里没有渐变、没有光晕、没有装饰性英文 eyebrow、没有逐元素入场动画。界面的"装饰预算"只花在三处：状态点、当前分区指示、变更条。
- **工具质感**：控件小而准（28px 高控件、44px 行高），密度高于 v3（v3 参数行 48px、控件 32–34px：按钮 32，NaiveUI medium 输入约 34）。留白靠**分区间距**（32px）而不是全局放大。
- **信息分层靠三件事**：字重（400/500/600）、文字颜色（ink / ink-2 / muted）、空间（分区 32 / 组 16 / 行 0）。**不靠字号**：v4 的字号阶只有 17 / 15 / 13 / 12 / 11，比 v3 的 28/20/15/13/12/11 更平——这是刻意的，28px 的 `RUNNING` 曾经抢走了整个窗口的注意力。
- **机器数据永远等宽**：命令行 flag、路径、端口、版本、日志、变更前后值。**等宽字不用于中文标签、不用来"显得专业"**。
- **两套主题同等对待**：深色是"参考氛围"（默认跟随系统），浅色是"白天办公室"版本，不是深色的反相补丁。

**参考坐标（Codex 一类现代 agent 应用 / Linear / Zed / VS Code）**

| 借鉴（Keep） | 改写（Change） | 不抄（Do not copy） |
|---|---|---|
| 深色中性画布 + 发丝线分区，几乎不用投影 | 色值改为本方案的石墨/冷蓝，面差自己定 | 它们的品牌色、logo、产品名 |
| 等宽字只承载机器数据 | 用在本产品的 flag、路径、日志、版本、变更值 | "等宽字排中文标题"的科技感做法 |
| 命令面板作为第二导航，键盘优先 | 只搜参数/操作/服务/设置，不做 AI 助手 | 会话/对话式信息架构与"提示词"话术 |
| 写入前先看 diff / 审批 | 常驻可查的审阅浮层 + 四层脏标记 | 它们的审批卡文案、截图文案、定价 |
| 上下文动作：只给当前状态可用的动作 | 运行中/已停止/过渡各一套（见 §11.2） | 大色块与渐变标题的营销视觉 |
| 安静的空状态、骨架屏、行内错误 | 版式与文案全部自写 | 全屏 loading、遮罩式忙碌态、"AI 生成中"动画 |

### 2.3 颜色规则（比色值更重要）

1. **填写 = 墨。** 深色模式主按钮是暖白底黑字（`--text` 填充 / `--bg` 文字，16.31:1），浅色模式是墨底白字（18.43:1）。蓝色**不做**填充按钮：深色下白字压 `#7CA5FF` 只有 2.42:1。
2. **蓝色只做交互态**：焦点环、当前页签指示、选中行、链接、滑块已填充段。一屏内蓝色面积不超过 2%。
3. **状态色只做状态**：点、状态芯片、未应用角标、危险文字。绝不做背景大面积、绝不做装饰。
4. **不使用纯黑 `#000`**：深色最深处是 `#0E0E0D`（带 1 点暖）。浅色不使用纯白页面底（`#F4F4F1`），只有内容面是 `#FFFFFF`。
5. **层级靠"面差"**：侧栏/应用栏 `--bg` → 内容面 `--surface` → 输入 `--field`，三级面差约 3–4% 亮度，比投影可靠。

## 3. Typography

全部 Windows 本地字体（ADR-0001：禁止远程字体、禁止 CDN）：

```css
--font-ui:   "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif;
--font-head: "Segoe UI Variable Display", "Segoe UI", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif;
--font-mono: "Cascadia Code", "Cascadia Mono", Consolas, "DejaVu Sans Mono", monospace;
```

| 角色 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `title` | 17 / 1.35 | 600 | 工作区服务名、弹层主标题（**全窗口最大字号**） |
| `subtitle` | 15 / 1.4 | 600 | 变更审阅、设置、空状态标题 |
| `body` | 13 / 1.55 | 400·500·600 | 行标签、输入、按钮、正文 |
| `small` | 12 / 1.55 | 400·500 | 页签、说明、侧栏次级、工具条 |
| `meta` | 11 / 1.45 | 400·500 | 时间戳、计数、单位、`kbd`、变更前值 |
| `mono` | 13 / 1.5 | 400 | 数值读数（与标签同基线，`tabular-nums`） |
| `mono-sm` | 12 / 1.62 | 400 | 真值行、日志、命令原文、路径 |

规则：

- 中文行高 ≥1.5；13px 中文用 1.55，12px 日志用 1.62。
- **不加字距**（中文不需要），只有 `kbd` 与拉丁 acronym 允许 `+0.02em`。
- **不做全大写英文 eyebrow**（v3 的 `SERVICE / CONFIGURATION / SESSION LOG` 在中文界面里是纯装饰）：结构标签用中文 12px `--text-2`，机器名（NSSM、server.err、AppParameters）保留原文。
- 数字一律 `font-variant-numeric: tabular-nums`；数值列右对齐，宽度按最宽允许值预留，避免拖动时抖动。
- 长路径**不换行**：单行 `text-overflow: ellipsis`，`title` 给全路径，可复制；路径的"尾部文件名"优先可见（用 `direction: rtl` 的文本技巧或前端截断，二选一，实现时定）。
- 不用 `text-transform: uppercase` 处理中文。

**滚动契约（唯一一个容易做错的地方）**

- App bar / Sidebar / Workspace header / Tabs / Commit bar / Dock 全部 `flex: none`，永不参与滚动。
- 工作区内**只有一个**滚动容器（`.pane`），Toolbar 与分区标题 `position: sticky` 在它内部。
- Sidebar 独立滚动（服务多时）。
- Dock 展开时**占据高度**：压缩工作区与侧栏，不覆盖任何内容；提交条始终紧贴在 Dock 之上，改参数时不会被日志盖住。Dock 横跨整个窗口宽度（含侧栏下方），是为了让 llama.cpp 的长行日志拿到最长行宽；侧栏在 Dock 上方结束。（v3 的日志条同样占布局高度 —— `grid-template-rows: 0fr/1fr`，不遮挡提交条；它的问题是**与重启转录混在同一列表**、默认折叠，以及和提交条是两条相邻通栏，视觉上没有"系统带"的层次。）
- 侧滑浮层与命令面板是唯一的"覆盖"，且有 scrim。

### 5.3 导航模型


- **没有"返回"按钮**：三个页签是平级目的地；设置是模态窗，Esc 回来。

- 页签角标承载"待办"：`参数 · 3`（未应用更改数）、`维护 · 1`（可用更新）。这是全应用唯一的"红点"机制，不用 toast 催。

| Toast | 只在"后台事件"用（启动检查发现新版）；360 宽，右下，3s，带一个动作链接；不用来确认用户刚点的动作 |

## 7. Motion & Interaction

**原则**：动效只解释"什么变了"，不表演。整个应用只有四种移动。

| 场景 | 时长 / 曲线 | 属性 |
|---|---|---|
| hover / 按下 | 90ms `cubic-bezier(.2,.8,.2,1)` | background-color、color、transform(.98) |
| 状态切换（点、芯片、角标） | 140ms | opacity、color |
| 侧滑浮层 / 抽屉展开 | 180ms 进 / 140ms 出 | transform、grid-template-rows |
| 命令面板 | 160ms 进 / 100ms 出 | opacity + translateY(4→0) |

- 曲线统一：进入 `cubic-bezier(.2,.8,.2,1)`（快出慢停），退出 `cubic-bezier(.4,0,1,1)`（直接走）。
- **不做的**：逐元素入场（v3 的 `enter-1..6` 全部删除）、页面切换位移、列表项 stagger、按钮 ripple、发光。
- **进行中**：工作区头部下沿 1px 不确定进度条（`--accent`，1.4s 循环）；状态点呼吸；dock 里显示当前步骤文本。不做全屏遮罩。
- **减少动效**：设置里的总开关 + `prefers-reduced-motion: reduce` 同时把时长压到 0.01ms（沿用 v3 的正确做法：动画"瞬间到终态"，不是"取消状态变化"）。
- **不做布局跳动**：状态变化不改变头部高度（真值行始终占位，空值写 `—`）；行内原值出现时预留 56px 行高（用 `min-height` 而不是插入后撑开）。
- 滚动容器 `scroll-behavior: auto`（不做平滑滚动，改参数时最烦"飞过去"）。

## 8. Voice & Brand

**语气**：短句、事实优先、动词开头、不感叹、不用"请"堆礼貌。

| 场景 | 不要 | 要 |
|---|---|---|
| 空服务 | "暂无数据" | "未发现 NSSM 服务" / "先在命令行注册服务，再重新扫描" |
| 未应用 | "有未应用的更改" | "3 项未应用" |
| 写入结果 | "操作成功" | "已写入 3 项 · 需重启后生效" |
| 失败 | "出错了" | "写入失败：拒绝访问（sc 返回 5）" + `[复制详情]` |
| 更新 | "发现新版本，是否更新？" | "最新 b5610（当前 b5527）· 2025-03-14" + `[查看更新说明]` |
| 忙碌 | "请稍候…" | "正在重启 llama-prod…" + 当前步骤 |

**术语**（沿用 `CONTEXT.md`，设计不得改写）：服务 / AppParameters / 字段 / Fact / 语义等价 / 未应用更改 / 应用 / 还原 / 预设 / 自动备份 / 构建版本 / 备份 / 回滚 / Snapshot。界面里不出现：配置、dirty、保存、提交、同步、实例、config。

**品牌**：

- 名称 `llama-ctl`（应用栏 13/600），副行不放"服务控制台"——窗口标题已经是它。
- 标记：保留现有 16 网格 λ 图标（`AppShell.vue` 内联 SVG），20px 盒 + 圆角 6 + `--text` 填充 + `--bg` 描边；**不重新设计 logo**（不在本轮范围）。
- 图标：保留 `Icon.vue` 的 16 网格 / 1.5 描边 / 圆头 / `currentColor`；v4 新增 `command`、`chevron-up/down`、`copy`、`folder`、`refresh-cw`、`arrow-right`、`x`、`plus`、`trash`、`external`、`terminal`。不给图标配彩色。
- 主按钮永远不带动画图标；spinner 只在"真的在等"的地方出现。

## 9. Anti-patterns（逐条，可验收）

1. **不做 28px 的巨型状态词**。全窗口最大字号 17px（服务名）。
2. **同一事实不出现两次**。状态只在真值行；服务列表只有点，不再有第二枚"状态 pill"。
3. **不用一条 280px 轴线贯穿三个部件**。v4 只有一根内容左边界。
4. **不把 7 个分区做成手风琴**。分区平铺 + 分区目录；搜索不是唯一找参数的方式。
5. **不把 diff 提前放进对话框**。差异是常驻可查的浮层。
6. **不用全局 `busy` 灰掉整个界面**。只禁用会冲突的命令。
7. **不用 mono 写中文标签**、不用"全大写英文 eyebrow"当装饰。
8. **不用渐变、玻璃拟态、彩色阴影**。模糊只用在命令面板的 scrim。
9. **不做逐元素入场动画**，任何动画 ≤240ms。
10. **不用 40% 不透明度假装禁用**（对比度会掉到 2:1）；禁用态用 `--field` + `--muted` 实色。
11. **不用 hover 作为唯一入口**：行内"重置此项"必须键盘可达（Tab 到行尾 gutter）。
12. **不隐藏错误**：失败不弹 toast 就完事，必须在出错的位置留下可复制的文本。
13. **不在中文里塞英文介词结构**（"Update 这个 Service"），也不机翻 `Fact`/`Apply`。
14. **不做"设置页=另一个世界"**：设置是模态窗，服务状态始终在背景可见。
15. **不在 880px 下把导航折叠进汉堡菜单**。

## 11. 交互流程

### 11.1 启动

```
mount → phase=loading（骨架）→ refresh() → phase=ready（内容交叉淡入 120ms）
                                     ↘ phase=error（错误条 + 上次数据，若有）
ready 后：恢复窗口几何（只在第一次拿到 settings.geometry 时）→ 订阅 restart/update 进度 → 静默检查更新
```

规则：静默检查只提示（页签角标 + toast 一条），永不自动下载/安装（沿用 ADR / ticket 15 的既有约束）。

### 11.2 改一个参数并应用（主干路径）

```
1 定位   页签/目录/Ctrl K/搜索  → 聚焦控件
2 编辑   输入或拖动 → 前端表单值变化（不写服务）
3 反馈   行内"↳ 原 32"出现；分区"已改 1"；页签"参数 · 1"；提交条升起 48px
4 审阅   [应用更改] → 变更审阅浮层（旧值→新值；运行中则提示需重启）
5 执行   确认 → 按钮 spinner + 头部进度条 + Dock 活动追加一行
6 结果   Rust 返回新 Snapshot → 浮层关闭 → 提交条变成结果行
         运行中："已写入 1 项 · 需重启后生效 [重启服务]"
7 收尾   [重启服务] → 确认 → 活动流逐行追加（停止 → 启动 → 等待就绪）→ 真值行更新（RUNNING + 新 detail）
```

失败分支：`apply` 返回错误 → 浮层保留（不关），底部显示错误行 + `[复制详情]`；表单值不清空（用户的东西不能丢）。

### 11.3 还原（可撤销）

```
[还原] → 立即生效（不回滚服务，只从 Snapshot 重读）→ 提交条下方出现一行：
"已还原到服务的 28 项参数 · [撤销]（10s）"
```

- 撤销是前端持有被丢弃的表单 10 秒（表单本就是前端唯一持有的状态，不违反契约）。
- 10 秒后或下一次编辑后，撤销入口消失。

### 11.4 切换服务 / 载入预设（有未应用更改时）

```
点击另一个服务（或预设）
  ├─ dirty=false → 直接切换（命令 → 新 Snapshot）
  └─ dirty=true  → 切换审阅浮层
       ├─ [另存为自动备份并切换]  主按钮（autoBackupName 生成名字）
       ├─ [放弃更改并切换]       危险文字按钮
       └─ [取消]                 Esc
```

- 浮层里列出"将被放弃的 3 项改动"（与变更审阅同一组件，只换底部按钮），比 v3 的确认框更能说明放弃什么。
- 自动备份是预设，不写服务；把它分到预设页的"自动备份"组。

### 11.5 预设的生命周期

| 动作 | 结果 | 许可 |
|---|---|---|
| 另存当前为预设 | 存表单值；重名则禁用保存并说明 | 写本地预设文件（Rust） |
| 载入 | 只填表单；不写服务；dirty 时先审阅 | 只读 |
| 删除 | 确认框（不可逆）→ 删除 | 写 |
| 自动备份 | 在脏切换时生成，名字带时间戳 | 写 |

### 11.6 重启

```
[重启] → 确认框（"重启将中断进行中的推理"）→ 活动流：停止 → 启动 → 探活
成功：真值行 RUNNING + detail；活动组折叠为"重启 · 4 行 · 3.2s ✓"（"等待就绪"按秒追加，行数随探活时长变化）
失败：活动组保持展开，失败步骤红标，服务状态可能为 STOPPED（真值行如实显示）
```

### 11.7 更新

```
维护页 → [检查更新]（只读）→ 结果三态：已是最新 / 有新版本（版本卡 + 说明）/ 未知
有新版本 → [立即更新] → 确认框（写明"将停止服务 s、备份到 d"）
        → 步骤器逐行推进 → 成功：结果行 + 版本卡刷新 + 页签角标清除
                         → 失败：步骤器停在失败步 + "已回滚" + [复制详情]/[重试]
```

### 11.8 失败恢复矩阵

| 失败 | 用户看到 | 可做 |
|---|---|---|
| 首帧读取失败 | 错误条 + 上次数据 + 时间戳 | 重试、复制详情 |
| 写入失败 | 审阅浮层不关 + 错误行 | 重试、复制、取消 |
| 重启失败 | 活动流停在失败步 | 复制、重试、查看日志 |
| 探活失败（服务 RUNNING 但不健康） | 真值行 detail 写 FAIL | 查看日志、重启 |
| 安装失败 | 步骤器 + 回滚说明 | 复制、重试、查看日志 |
| 解析告警 | 参数页参数区上方告警条（可折） | 复制、跳维护看原文 |

## 13. 无障碍

- 对比度：§2.2 已实测；`smoke.mjs` 里现有的 ≥4.5 守卫扩展到新令牌，**并新增**控件描边 3:1 的守卫。
- 焦点：`2px --accent` + 2px offset；浮层打开时焦点移入首个可操作项，关闭后回到触发元素；不做 `outline: none` 却不给替代。
- 语义：页签用 `role="tablist"/"tab"/"tabpanel"` + `aria-selected`；状态芯片 `role="status"`（`aria-live="polite"`）；错误条 `role="alert"`；活动流 `role="log"`；参数用真 `<label for>`，滑块 `aria-valuemin/max/now/text`；数值输入 `aria-describedby` 指向帮助浮层 id。
- 不以颜色单独表达：状态=点+文字；已修改=竖条+`↳ 原值`+分区计数；焦点=环+2px。
- 键盘可达：服务列表（↑↓ + 切换）、页签、每行重置、Dock 页签与工具、浮层按钮。
- 屏幕阅读器：图标按钮全部 `aria-label`；`kbd` 提示用 `aria-keyshortcuts` 挂在真实控件上（不做纯视觉提示）。
- 动效：见 §7；闪烁/呼吸频率 ≤1.2s 且只在过渡态。

## 16. 验收标准（可测）

**布局**

1. 1080×820 下参数页首屏可见 **≥8 行**参数（视觉稿实测 9 行）；服务名、真值行、页签、工具条、提交条同屏不重叠。
2. 880×640 下**无横向滚动条**；最长的真实路径（`F:\models\Qwen3-32B-Q4_K_M.gguf`）在模型行内不换行、不遮按钮，title 可看全。
3. 状态在 RUNNING ↔ STOPPED ↔ 过渡 ↔ 未知之间切换时，头部高度不变（±0px），内容不位移。
4. 全窗口只有一个"最大字号"元素（服务名 17px）；不存在 20px 以上的文本。

**交互**

5. 从打开应用到"改完一个参数并写入"≤5 次点击（页签已在该页时为 4 次：控件 → 应用 → 应用并重启 → 重启确认）。
6. 有未应用更改时，切服务 / 载入预设 / 关闭窗口都必须先出现审阅浮层，且浮层里能读到"将放弃哪几项"。
7. `busy` 期间用户仍能切页签、看日志、滚动参数（只禁用冲突命令）。
8. 任一写服务动作的结果都来自**新 Snapshot**；UI 不得先改本地状态再等确认（含自启开关、频道选择）。
9. 还原后 10 秒内可撤销，撤销恢复**全部**被丢弃字段。
10. 命令面板可到达 28 个参数、全部 8 个操作、N 个服务；执行操作时不得跳过确认。

**视觉**

11. 两种主题下所有文本 ≥4.5:1、所有可交互描边 ≥3:1（用 §2.2 的值做守卫）。
12. 一屏内蓝色像素面积 <2%（目测 + 截图取样）；不存在渐变与彩色阴影。
13. 禁用态文字对比度 ≥4.5:1（不是 40% 透明）。
14. 侧栏/内容/字段三级面差在两种主题下都能分辨（截图灰度差 ≥2 级）。

**动效与无障碍**

15. 所有动效 ≤240ms；`motion-off` 与 `prefers-reduced-motion` 下为 0.01ms 且终态正确。
16. 仅用键盘可完成：切服务 → 改一个数值 → 应用 → 打开 Dock → 关设置。
17. 焦点环在 8 类控件上可见；浮层焦点锁定并正确归还。
18. 屏幕阅读器可读出：状态（`role=status`）、错误（`alert`）、活动流（`log`）、页签选中态。

**工程边界**

19. 不新增运行时依赖（NaiveUI 已有能力不够的地方用原生 DOM）。
20. 不新增远程请求 / 外链 / 远程字体（ADR-0001）。
21. 新增文案全部进 `core::i18n`（或 `commands::copy`），前端不自带翻译。
22. `frontend/smoke.mjs` 现在**按 token 断言**半径（`CARD 12px / CONTROL 8px / CHIP 6px`）、`ACC`/`PRIMARY` 的具体值、以及 NaiveUI 的 `primaryColor`/`infoColor`/`borderRadius` overrides（L171–L216）。v4 改半径与取消森林绿之后，必须同步改写这些断言（10/6/4 + 冷蓝），**不能为了让构建变绿而删掉守卫**。

## 17. 风险、取舍与未知

| 项 | 取舍 | 风险 / 缓解 |
|---|---|---|
| 去掉手风琴 | 28 个字段全平铺 | 滚动变长 → 分区目录 + 命令面板 + 粘顶分区标题；分区目录在 <1080 隐藏（此时靠命令面板） |
| 预设从底栏变整页 | 多一次点击 | 预设是低频操作；换来的是能看清"哪些是自动备份" |
| 设置改模态窗 | 设置里的更新搬到维护页 | 用户可能先去设置找更新 → 设置页"关于"下方放一行"更新在 维护 页"的指引 |
| 侧栏显示其它服务不显示状态 | 没有逐服务 probe 接口 | 未探测用中性点；鼠标悬停写"状态未读取"；不编造 |
| 自动备份按名称前缀分组 | 只是字符串约定 | 文案不宣称"系统分组"；后端加元数据后可升级 |
| 审阅浮层替代确认框 | Apply 少了一次"模态确认"的仪式感 | 浮层本身就是二次确认（按钮文案含后果）；不可逆操作（删除预设、安装更新）仍是模态 |
| Dock 来源分离 | 用户要找重启步骤 | 活动页签命名 + server.err 头部交叉链接 |
| 真值行依赖 `detail` 原文 | 无法结构化对齐 | 原文等宽 + 截断 + tooltip + 可复制；结构化留给后端 |
| 字号阶压平（最大 17） | 页面"气势"变弱 | 靠密度与面差建立专业感；这也是本次换方向的核心判断，若评审认为"太素"，优先加**面差与间距**，不加字号 |

**未决（需要评审拍板）**

1. 是否保留"运行概览"作为独立第四页签（含探活历史）？当前判断：不做——没有历史数据源，做了也是空壳。
2. 侧栏是否需要"最近使用"排序？当前保持 Rust 返回顺序（稳定）。
3. 是否接受"设置=模态窗"从而让"更新"离开设置？当前判断：接受（更新是服务维护，不是偏好）。

**本轮没有做、也没有假装做的事**：没有改任何代码、没有跑构建、没有生成视觉稿图片；OpenDesign 需求卡已开出但**尚未由人确认**，本方案的依据是：仓库代码实测（文件路径与数值均在正文标注）+ 用户本轮指令 + `reference-design-contract` 的方法。
